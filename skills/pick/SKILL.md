# pick: 스킬 고르기 · 찾기 · 만들기

## 왜 있는가
스킬을 쓰는 진짜 목적은 **반복 업무를 줄이고 토큰을 아끼는 것**이다. 그런데 사용자는 (1) 스킬을 하나하나 찾기 어렵고, (2) 직접 만들기 어렵고, (3) 요즘 뜨는·많이 쓰는 스킬이 뭔지 모른다.
그래서 매번 **설치된 스킬 + 설치 안 된 인기·트렌드 스킬 + 새로 만들기**를 한 화면에 나란히 보여 주고 고르게 한다.
매핑 표와 예전 선택은 정답이 아니다. 늘 같은 스킬만 권하면 이 스킬은 실패한 것이다.

## 순서
1. 요청을 한 줄로 요약하고, 영어 키워드 2~3개를 뽑는다. 대상(kiosk)이 아니라 **필요한 능력** 위주로 고른다. 스킬 이름은 능력으로 지어지기 때문이다. 예: 키오스크 리디자인 → `design ui ux`, 미드저니 표지 → `image prompt midjourney`.
2. **매번** 로컬 카탈로그를 한 번 훑는다(네트워크 0, 1초 미만):
   `bash ~/.claude/skills/pick/scripts/find.sh --local <키워드>`
3. 최근 기록을 본다: `tail -n 30 ~/.claude/skill-archive/pick-history.tsv 2>/dev/null`
   - **반복 감지**: 이번 요청과 같은 종류(요약이 비슷하거나 고른 스킬이 같음)가 3번 이상이면 반복 업무다. 대화에서 "또", "매번", "늘 하는"이 나와도 반복으로 본다. 반복이면 "만들기"를 1순위 후보로 올린다. 반복 절차를 스킬·스크립트로 고정하면 다음부터 설명·탐색 토큰이 줄기 때문이다.
4. 후보를 세 칸으로 채운다.
   - **설치된 스킬** 최대 2개: 매핑 표와 세션 전체 스킬 목록에서. 근거는 "요청의 어떤 말 ↔ 스킬 설명의 어떤 말"로 댄다. "표에 있어서", "학습 줄에 있어서"는 근거가 아니다. 그것만 있고 설명이 요청과 안 맞으면 후보에서 뺀다.
   - **새 스킬** 최대 2개: 2번 결과 중 설치 안 된 것. 공식이거나 스타 1,000 이상인 것만 본다. 점수(이름 일치)는 참고일 뿐이고, 설명이 요청과 실제로 맞는지 직접 판단한다. 처음 키워드로 맞는 게 없으면 다른 능력 키워드로 `--local`을 한 번 더 돌린다. 그래도 없으면 "맞는 새 스킬 없음"이라고 적는다.
     `3-popular`·`3-trending` 줄의 설명은 레포 설명이다. 후보로 올리기 전에 `find.sh --desc <위치>`로 그 스킬의 진짜 설명을 확인한다(후보당 1번, 최대 2번).
   - **만들기** 1개: 아래 "맞춤 스킬 만들기" 조건에 맞거나, 위 두 칸이 모두 약할 때.
   - 후보마다 네 가지를 채운다: **하는 일**(쉬운 말), **근거**(요청 말 ↔ 설명 말), **토큰**(설치된 것은 `find.sh --size <이름...>`로 한 번에, 새 스킬은 "미확인"), **반복 절감**(이 작업이 또 오면 스킬이 절차·스크립트로 대신해 주는지).
5. 쏠림 점검: 3번 기록에서 최근 5번 중 3번 이상 1순위였던 스킬은, 이번 요청과의 근거가 다른 후보보다 분명할 때만 1순위로 둔다. 아니면 2순위로 내리고 이유를 한 줄 적는다.
6. 고르게 한다.
   - **근거 있는 후보가 1개뿐**이면 묻지 않고 `선택: <이름> — <근거>` 한 줄만 알리고 진행한다. 고를 게 없는데 묻는 것은 시간·토큰 낭비다.
   - 2개 이상이면 AskUserQuestion **한 질문**으로 묻는다. 칸마다 선택지 하나(최대 4개):
     - label: `[설치됨] 이름` / `[새 스킬] 이름` / `[만들기] 이름` (짧게. 함께 써야 하는 조합이면 `A + B`)
     - description: 하는 일 + 근거를 한 문장으로. 근거가 가장 강한 하나에만 끝에 `(Recommended)`.
     - preview: 아래 네 줄 고정.
       ```
       하는 일: …
       근거: "요청의 말" ↔ "설명의 말"
       토큰: 약 N (설치된 것) / 미확인 (새 스킬)
       반복 절감: … / 설치: 필요 없음 | <위치>
       ```
     사용자는 "Other"로 직접 적거나 섞어 달라고 할 수 있다.
7. 답대로 진행한다.
   - 설치된 스킬 → Skill 도구로 불러 수행. 이후 작업 중에는 다시 묻지 않는다.
   - 새 스킬 → 아래 "새 스킬 설치" 3단계로(설치는 거기서 한 번 더 확인).
   - 만들기 → "맞춤 스킬 만들기"로.
8. 기록한다. `~/.claude/skill-archive/pick-history.tsv`에 한 줄 추가(폴더 없으면 만든다):
   `날짜<TAB>요청 요약<TAB>1순위 후보<TAB>사용자 선택`
   사용자가 1순위가 아닌 것을 골랐으면 매핑 표의 해당 줄을 그 선택으로 고치고 `(학습 날짜, 1회)`를 붙인다(이미 같은 선택이면 횟수만 +1). 표에 없던 작업이면 줄을 추가한다.

### 묻지 않고 바로 진행하는 경우
- 요청에 스킬 이름을 직접 적었다.
- 같은 대화에서 같은 종류 작업을 이미 확인받았다.
- "요즘 뜨는 스킬", "좋은 스킬 뭐 있어?"처럼 목록만 원한다 → `find.sh --top 15` 결과를 표로 보여 주고 끝(설치는 묻지 않는다).

### 토큰 절약 스킬
- `pick`은 `caveman`을 따로 불러오지 않는다. 사용자가 켰다면 그 스킬 규칙대로 이미 유지된다.
- 코드·스크립트를 쓰는 작업에만 `ponytail`을 후보 줄 끝에 `(+ponytail)`로 붙인다.
- 읽기는 필요한 부분만, 같은 내용 반복 조회 금지.

## 맞춤 스킬 만들기
조건(하나라도):
- 사용자가 "스킬 만들어줘"라고 했다.
- 반복 업무다(3번 반복 감지 참고).
- 있는 스킬이 일반론만 알고 이 프로젝트의 규칙·파일 구조·용어를 모른다.
- 같은 프로젝트에서 비슷한 요청이 반복된다(pick-history, 대화 기록, CLAUDE.md로 확인).
- 설치된 스킬도 새 스킬도 근거가 약하다.

선택되면:
0. 만들기 전에 `find.sh <키워드>`로 비슷한 인기 스킬을 찾아 상위 1~2개의 SKILL.md만 읽고, 구조·좋은 규칙을 참고한다. 그대로 복사하지 않고, 참고한 레포를 새 SKILL.md 끝에 `참고:`로 적는다. 바퀴를 다시 만들지 않기 위해서다.
1. `anthropic-skills:skill-creator`를 불러 **가벼운 모드**로 만든다: 의도 정리 → 초안 → 실제 요청 1건으로 바로 사용(별도 평가 반복·뷰어 생략, 사용자가 원할 때만 추가 테스트).
2. 위치: 현재 프로젝트의 `.claude/skills/<이름>/SKILL.md`. 프로젝트 폴더가 없으면(홈 디렉터리 등) 어디에 둘지 묻는다.
3. 내용은 이 프로젝트에서 확인한 사실만: 폴더 구조, 쓰는 도구·컴포넌트, 이름 규칙, 사용자가 이 대화에서 고친 점. 설치된 스킬이 이미 다루는 일반론은 다시 쓰지 말고 "X 스킬과 함께 쓴다"로 연결한다.
4. 토큰을 아끼게 만든다: 매번 똑같이 하는 단계(파일 찾기, 변환, 검사)는 `scripts/`에 스크립트로 넣고 SKILL.md에는 실행 한 줄만 적는다. SKILL.md는 150줄 이하, 긴 참고 자료는 `references/`로 나눈다. 스크립트는 macOS·윈도우(Git Bash) 둘 다 도는 bash로.
5. 만든 뒤 그 SKILL.md를 Read해서 바로 이번 요청에 적용한다(새 세션을 기다리지 않는다).
6. 매핑 표에 `| <작업> (<프로젝트명>) | <새 스킬> |` 한 줄을 추가한다.

## 매핑 (출발점일 뿐, 정답 아님)

## 새 스킬 설치 (외부 스킬)
2번 로컬 결과에 쓸 만한 게 없고 사용자가 새 스킬을 원하면 더 넓게 찾는다.

```bash
bash ~/.claude/skills/pick/scripts/find.sh <keyword> [keyword2]   # 오래된 캐시 갱신 + 필요하면 깃헙 실시간
bash ~/.claude/skills/pick/scripts/find.sh --all <keyword>         # 실시간 검색까지 강제
```

찾는 순서: 제거 기록(복구가 가장 빠름, `prune` 참고) → 공식·Anthropic 카탈로그(`1-official`, `2-anthropic`, 30일 갱신) → 인기·트렌드 카탈로그(`3-popular`, `3-trending`, 7일 갱신, 6개월 넘게 커밋 없는 레포 제외) → 깃헙 실시간.
- 출력은 `점수, tier, 위치, 스타, 설명`. `[같은 이름 설치됨]`은 이름만 같을 수 있으니 설명을 보고 판단한다.
- 스크립트 실행은 요청 1건당 최대 2번.

### 2. 비교 → 상위 3개 추리기
| 기준 | 보는 것 |
|---|---|
| 신뢰도 | 출처(공식 > Anthropic 레포 > 그 제품을 만든 회사 레포(vercel-labs, microsoft 등) > 개인), 스타 수(100 미만은 의심), 최근 6개월 안 커밋, 라이선스, 스크립트가 하는 일 |
| 프로젝트 적합도 | 지금 프로젝트의 언어·도구·작업 방식과 맞는지(폴더 구성, CLAUDE.md로 확인). 스타가 높아도 프로젝트에 안 맞으면 뒤로 |
| 토큰 | SKILL.md 길이, 참조 파일 분리 여부. 같은 일을 하면 짧은 쪽 |
| 효율 | 필요한 추가 설치·의존성 수 |

- 종합해 **최대 3개**를 순위대로 추린다. 동점이면 출처 순서를 따른다.
- 추린 후보의 SKILL.md 앞부분만 읽어 무엇을 하는지 확인한다. 제3자 스킬은 설치 직전에 SKILL.md와 포함 스크립트를 끝까지 읽고, 외부 전송·자격증명 접근·파괴적 명령이 있으면 뺀다.

### 3. 설치 여부 묻기 (무조건, 최대 2번)
- **1차**: AskUserQuestion 한 번에 추린 후보를 나열한다. 후보마다 한 줄: `이름 — 무엇을 하는 스킬 — 출처(★스타) — 이 프로젝트에 맞는 이유`. 질문 본문 끝에 설치될 위치를 적는다. 선택지: 후보 1~3(1순위에 Recommended) / 설치 안 함.
  - 고름 → `~/.claude/skills/<이름>/`에 설치(공식 플러그인이면 플러그인 설치 방식) → 그 스킬로 작업 수행.
  - 설치 안 함 → 1차 후보를 모두 제외하고 `find.sh --all`(필요하면 다른 키워드)로 다시 찾아 새 후보를 추린다.
- **2차**: 새 후보로 같은 방식으로 한 번 더 묻는다.
  - 허용 → 설치 후 수행.
  - 거부 → 더 찾지 않는다. 설치 없이 **지금 있는 스킬 중 가장 가까운 것**으로 진행하고, 그렇게 한 줄로 알린다.
- 허락 없이 설치하지 않는다. 2차 이후에는 다시 묻지 않는다.
- 세 곳 모두 쓸 만한 후보가 없으면 묻지 않고 있는 스킬(없으면 스킬 없이)로 진행하고 그렇게 말한다.
