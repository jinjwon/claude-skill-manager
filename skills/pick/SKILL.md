# 스킬 추천 (후보 제시 → 확인 → 실행)

직접 후보를 골라 오되, 실행 전에 한 번만 확인받는다. 표만 보고 늘 같은 스킬을 고르는 실수를 막기 위해서다.

## 순서
1. 요청(인자 또는 직전 메시지)을 한 줄로 요약한다.
2. 후보를 고른다. **매핑 표와 세션의 전체 스킬 목록을 둘 다** 본다. 표는 출발점일 뿐이다. 목록에서 설명이 요청에 더 딱 맞는 스킬이 있으면 그것을 우선한다.
   - 추천 조합: 최대 3개, "과정 스킬 → 도구 스킬" 순서. 토큰 절약 스킬은 개수에서 빼고 따로 표시.
   - 대안: 추천과 다른 접근 1~2개(있을 때만).
   - 맞춤 제작: 아래 "맞춤 스킬 제작" 조건에 해당하면 후보로 넣는다.
3. AskUserQuestion으로 **한 번** 확인한다. 질문 본문에 후보마다 한 줄씩:
   `이름 — 무엇을 하는 스킬인지(쉬운 말, 15자 안팎) — 이 요청에 쓰는 이유`
   선택지(상황에 맞게 2~4개):
   - **추천대로 진행** (Recommended) — 추천 조합 그대로
   - **대안으로 변경** — 대안 스킬 이름을 라벨에 적는다
   - **추천 + 추가** — 더할 만한 스킬 이름을 라벨에 적는다. 대안과 같은 스킬을 넣지 않는다. 더할 게 없으면 이 선택지를 뺀다
   - **맞춤 스킬 제작** — 조건에 해당할 때만
   사용자는 "Other"로 직접 스킬 이름을 적을 수도 있다.
4. 답대로 Skill 도구로 불러 수행한다. 이후 작업 중에는 다시 묻지 않는다. (예외: 새 스킬 설치는 "스킬이 없을 때" 절차대로 따로 묻는다.)
5. 고른 결과를 매핑 표에 반영한다. 사용자가 대안·추가·직접 입력을 골랐으면 그 작업 행을 사용자 선택으로 고치고, 표에 없던 작업이면 행을 추가한다. 추천대로 진행했으면 표를 건드리지 않는다. 같은 실수를 다음 요청에서 반복하지 않기 위해서다.

### 확인을 건너뛰는 경우
- 사용자가 요청에 스킬 이름을 직접 적었으면 묻지 않고 그 스킬로 바로 진행한다.
- 같은 대화에서 같은 종류 작업에 이미 확인받은 조합이면 다시 묻지 않는다.

## 맞춤 스킬 제작 (프로젝트 전용)
후보로 넣는 조건(하나라도 해당):
- 설치된 스킬이 요청의 핵심을 반만 다룬다(일반론만 있고 이 프로젝트의 규칙·파일 구조·용어를 모른다).
- 같은 프로젝트에서 비슷한 요청이 반복된다(대화 기록·CLAUDE.md로 확인).

선택되면:
0. 만들기 전에 `find.sh <키워드>`로 비슷한 인기 스킬을 찾아 상위 1~2개의 SKILL.md만 읽고, 구조·좋은 규칙을 참고한다. 그대로 복사하지 않고, 참고한 레포를 새 SKILL.md 끝에 `참고:`로 적는다. 바퀴를 다시 만들지 않기 위해서다.
1. `anthropic-skills:skill-creator`를 불러 **가벼운 모드**로 만든다: 의도 정리 → 초안 → 실제 요청 1건으로 바로 사용(별도 평가 반복·뷰어 생략, 사용자가 원할 때만 추가 테스트).
2. 위치: 현재 프로젝트의 `.claude/skills/<이름>/SKILL.md`. 프로젝트 폴더가 없으면(홈 디렉터리 등) 어디에 둘지 묻는다.
3. 내용은 이 프로젝트에서 확인한 사실만: 폴더 구조, 쓰는 도구·컴포넌트, 이름 규칙, 사용자가 이 대화에서 고친 점. 설치된 스킬이 이미 다루는 일반론은 다시 쓰지 말고 "X 스킬과 함께 쓴다"로 연결한다.
4. 만든 뒤 그 SKILL.md를 Read해서 바로 이번 요청에 적용한다(새 세션을 기다리지 않는다).
5. 매핑 표에 `| <작업> (<프로젝트명>) | <새 스킬> |` 한 줄을 추가한다.

## 토큰 절약 (항상 적용)
- 고른 스킬과 별개로 토큰 절약 스킬을 함께 불러온다:
  - 모든 작업: `caveman` (채팅 답변·중간 보고만 짧게. 결과물인 글·문서·슬라이드 문구에는 적용하지 않는다)
  - 코드·스크립트 작성(피그마 플러그인 코드 포함): `ponytail` (가장 작은 변경)
- 확인 질문에 `(+caveman, ponytail)`로 따로 표시한다. 추천 후보 3개 자리를 차지하지 않는다. 사용자가 빼라고 하면 뺀다.
- 읽기는 필요한 부분만, 같은 내용 반복 조회 금지, 스크린샷은 작업 뒤 1번만.

## 스킬이 없을 때 (외부 스킬 탐색·설치)

### 0. 먼저 있는 스킬로 해결 (탐색 금지 조건)
- 표에 없으면 현재 세션의 사용 가능한 스킬 목록에서 설명이 가장 맞는 것을 고른다.
- 설치된 스킬(또는 스킬 2개 조합, MCP 도구)로 요청의 핵심을 해낼 수 있으면 **외부 탐색을 하지 않고** 그 스킬을 쓴다.
- 외부 탐색은 "설치된 어떤 스킬로도 핵심 작업을 못 한다"고 판단될 때만 한다.
- 작업 도중 있는 스킬로 두 번 시도해도 막히면, 그때 외부 탐색을 제안한다(바로 찾지 말고 한 줄로 묻는다).

### 1. 후보 찾기 (스크립트 한 번)
직접 `gh`로 여기저기 검색하지 않는다. 아래 한 줄만 실행한다. 키워드는 영어 1~3개.

```bash
bash ~/.claude/skills/pick/scripts/find.sh <keyword> [keyword2]
```

스크립트가 싼 곳부터 보고, 이름이 맞는 후보가 나오면 멈춘다.
1. **제거 기록** (`~/.claude/skill-archive/removed.md`): 예전에 지운 스킬이면 바로 복구 후보다(복구 방법은 `prune` 참고).
2. **로컬 카탈로그 두 개** (네트워크 호출 없음):
   - 공식·Anthropic (`1-official`, `2-anthropic`): 30일마다 자동 갱신.
   - 인기·트렌드 (`3-popular`, `3-trending`): 스킬 관련 토픽 스타 상위 레포와, 최근 90일에 생겨 빠르게 뜬 레포의 스킬 목록. 7일마다 자동 갱신. 6개월 넘게 커밋 없는 레포는 이미 빠져 있다.
3. **깃헙 실시간**: 로컬에서 이름이 맞는 후보가 없을 때만.

- 출력은 `점수, tier, 위치, 스타, 설명` 순이고 점수 높은 순이다. `[설치됨]`이 붙은 것은 버린다(중복 설치 금지).
- 애매하면 `--all`로 실시간 검색까지 한 번 더 본다. 스크립트 실행은 요청 1건당 최대 2번이다.
- 사용자가 "좋은 스킬 뭐 있어?", "요즘 뜨는 스킬"처럼 목록 자체를 원하면 `find.sh --top 15`를 돌려 표로 보여 준다(설치는 묻지 않는다).

### 2. 비교 → 상위 3개 추리기
| 기준 | 보는 것 |
|---|---|
| 신뢰도 | 출처(공식 > Anthropic 레포 > 그 제품을 만든 회사 레포(vercel-labs, microsoft 등) > 개인), 스타 수(100 미만은 의심), 최근 6개월 안 커밋, 라이선스, 스크립트가 하는 일 |
| 프로젝트 적합도 | 지금 프로젝트의 언어·도구·작업 방식과 맞는지(폴더 구성, CLAUDE.md로 확인). 스타가 높아도 프로젝트에 안 맞으면 뒤로 |
| 토큰 | SKILL.md 길이, 참조 파일 분리 여부. 같은 일을 하면 짧은 쪽 |
| 효율 | 필요한 추가 설치·의존성 수 |

- 종합해 **최대 3개**를 순위대로 추린다. 동점이면 출처 순서를 따른다.
- 추린 후보의 SKILL.md 앞부분만 읽어 무엇을 하는지 확인한다. 제3자 스킬은 설치 직전에 SKILL.md와 포함 스크립트를 끝까지 읽고, 외부 전송·자격증명 접근·파괴적 명령이 있으면 뺀다.

### 3. 설치 여부 묻기 (무조건, 최대 2번)
- **1차**: AskUserQuestion 한 번에 추린 후보를 나열한다. 후보마다 한 줄: `이름 — 무엇을 하는 스킬 — 출처(★스타) — 이 프로젝트에 맞는 이유`. 질문 본문 끝에 설치될 위치를 적는다. 선택지: 후보 1~3(1순위에 Recommended) / 설치 안 함.
  - 고름 → `~/.claude/skills/<이름>/`에 설치(공식 플러그인이면 플러그인 설치 방식) → 그 스킬로 작업 수행.
  - 설치 안 함 → 1차 후보를 모두 제외하고 `find.sh --all`(필요하면 다른 키워드)로 다시 찾아 새 후보를 추린다.
- **2차**: 새 후보로 같은 방식으로 한 번 더 묻는다.
  - 허용 → 설치 후 수행.
  - 거부 → 더 찾지 않는다. 설치 없이 **지금 있는 스킬 중 가장 가까운 것**으로 진행하고, 그렇게 한 줄로 알린다.
- 허락 없이 설치하지 않는다. 2차 이후에는 다시 묻지 않는다.
- 세 곳 모두 쓸 만한 후보가 없으면 묻지 않고 있는 스킬(없으면 스킬 없이)로 진행하고 그렇게 말한다.
