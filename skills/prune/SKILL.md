# 스킬 제거 (안 쓰는 스킬 정리)

안 쓰는 스킬은 설명이 매 세션 컨텍스트에 실려 토큰을 쓴다. 호출 0회이면서 현재 프로젝트에 맞지 않는 것만 골라, 허락받고 치운다.

## 순서
1. 호출 횟수를 센다(한 번만 실행):
   `bash ~/.claude/skills/prune/scripts/usage.sh`
   출력: 이름, 전체 호출, 이 프로젝트 호출, 설치 후 일수, 설명. 호출은 실제 호출만 센다(Claude의 Skill 도구 호출 + 사용자가 입력한 `/명령`).
2. 제거 후보를 고른다. 아래 **세 조건을 모두** 만족해야 한다.
   - 전체 호출이 0회다.
   - 현재 프로젝트에 맞지 않는다. 프로젝트 성격(폴더 내용, CLAUDE.md, 최근 작업)과 스킬 설명을 견줘 판단하고, 이유를 한 줄로 댈 수 있어야 한다.
   - 설치한 지 14일이 넘었다. 막 설치한 스킬은 아직 쓸 기회가 없었을 뿐이다.
3. 후보마다 AskUserQuestion으로 허락을 받는다. 후보가 여럿이면 한 질문에 multiSelect로 묶는다(최대 4개씩). 각 항목에 반드시 넣는다:
   - 스킬 이름
   - 무슨 스킬인지 한 줄 설명(쉬운 말로)
   - 호출 0회, 설치 후 일수
   - 맞지 않는다고 본 이유
4. 허락받은 스킬만 제거한다. 거부한 스킬은 그대로 두고 다시 묻지 않는다.
5. 결과를 한 줄씩 알린다: 제거한 것, 남긴 것.

## 제거하지 않는 것
- `pick`, `prune` 자신.
- 호출이 1회라도 있는 스킬.
- 플러그인 스킬(`figma:…`, `superpowers:…` 등)과 `synced/` 안의 스킬. 낱개로 지울 수 없고 다음 동기화 때 되살아난다. 플러그인 전체가 0회면 "`/plugin`에서 끄면 된다"고 알려만 준다.
- 기록 범위(스크립트 첫 줄)보다 최근에 설치된 것이 아닌데 기록 자체가 짧으면(예: 7일 미만) 판단을 미루고 그렇게 말한다.

## 제거 방법 (지우되 되살릴 수 있게)
완전 삭제 대신 보관 폴더로 옮긴다. 스킬 목록에서는 사라져 토큰은 0이 되고, 나중에 재설치는 옮기기 한 번이면 끝난다.

```bash
mkdir -p ~/.claude/skill-archive
mv ~/.claude/skills/<이름> ~/.claude/skill-archive/<이름>
```

그다음 `~/.claude/skill-archive/removed.md` 끝에 한 줄을 추가한다(파일이 없으면 만든다). 형식은 고정이다. `pick`의 탐색 스크립트가 이 파일을 가장 먼저 검색하기 때문이다.

```
- <이름> | <날짜 YYYY-MM-DD> | 키워드: <영어·한글 검색어 3~6개> | 설명: <한 줄> | 출처: <원본 URL 또는 "직접 제작"> | 이유: <제거 이유> | 보관: ~/.claude/skill-archive/<이름>
```

마지막으로 `~/.claude/skill-archive/mapping.md`(pick 매핑 표)에 그 스킬이 있으면 해당 칸에서 뺀다. 없는 스킬을 고르는 일을 막기 위해서다.

사용자가 "완전히 지워"라고 분명히 말한 경우에만 보관 폴더의 사본도 지우고, 기록 줄의 `보관:`을 `없음(출처에서 재설치)`로 바꾼다.

## 다시 설치 (복구)
1. `grep -i <키워드> ~/.claude/skill-archive/removed.md`
2. `보관:` 경로가 있으면 `mv ~/.claude/skill-archive/<이름> ~/.claude/skills/<이름>`, 없으면 `출처:`에서 다시 받는다.
3. 기록 줄 맨 앞에 `[복구 YYYY-MM-DD]`를 붙인다(줄은 지우지 않는다. 이력이 남아야 같은 스킬을 또 제거 후보로 올릴 때 참고할 수 있다).
4. 새 세션부터 스킬이 보인다고 알린다.
